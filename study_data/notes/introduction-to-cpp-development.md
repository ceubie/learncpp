Simplistic development steps (this lesson covers 1–3):

1. Define the problem (what).
2. Decide how to solve it. This is the step people skip. Jumping straight into code often produces a fragile solution. A good solution is straightforward, documented, modular, and handles unexpected cases. On complex systems, most of a programmer’s time is maintenance, not the first draft.
3. Write the program in a text editor. The C++ you type is source code (or just code). Use a code editor, not a plain notepad: line numbers, syntax highlighting, and a fixed-width (monospace) font that distinguishes 0/O and 1/l/I.

A bug is any programming error that keeps the program from working correctly. Debugging is finding and removing bugs.

Best practice: name the first/primary source file `main.cpp`. Other extensions you may see: `.cc`, `.cxx`. Complex programs can have hundreds of source files.
